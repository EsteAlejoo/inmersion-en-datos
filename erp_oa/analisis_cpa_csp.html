Comparativa CPA vs CSP vs ERP OA
Evaluación por categoría de cumplimiento y funcionalidad

El CPA (Cuaderno de Plaguicidas y Agroquímicos) es el registro mínimo exigido por el SAG. El CSP (Cuaderno de Seguimiento de Plagas) es el instrumento de trabajo diario en Excel con 55 columnas. El ERP OA es el sistema interno de Órdenes de Aplicación que debe articular ambos. La tabla siguiente evalúa cada categoría en los tres instrumentos.

El CSP supera ampliamente los requisitos del CPA

El CPA exige 13 campos mínimos. El CSP cubre todos esos 13 campos más 42 campos adicionales que permiten trazabilidad operacional completa, análisis de desvíos, gestión de carencias y datos climáticos. Esto significa que el CSP ya contiene toda la información necesaria para generar el CPA automáticamente.

2
Hallazgo Crítico — El campo n° OA siempre está vacío
Brecha de integración entre el CSP y el ERP OA
🔴

Desconexión total entre el registro operacional y el sistema de órdenes

En la hoja "Aplicaciones" del CSP existe la columna n° OA (tercera columna, posición 3 de 55). Esta columna está vacía en todos los registros. Esto significa que ninguna aplicación registrada en el CSP puede ser rastreada hasta una Orden de Aplicación en el ERP, y viceversa. El ciclo planificación → ejecución → registro → compliance está roto.

2.1 Impacto del campo vacío

Impacto Situación actual (n° OA vacío) Situación objetivo (n° OA poblado)
Trazabilidad ❌ No se puede saber si la aplicación fue autorizada o espontánea. ✅ Cada registro CSP se vincula a una OA con agrónomo responsable y fecha de emisión.
Auditoría SAG/ASOEX ⚠️ No se puede cruzar la OA con el registro físico de campo. ✅ Auditor puede ir de la OA al registro CSP y al CPA en un solo clic.
Control de desvíos ❌ El % desvío en el CSP no puede compararse con lo que el ERP planificó. ✅ El ERP detecta desvíos automáticamente al cerrar la OA contra el CSP.
Facturación / costos ❌ No se puede costear la aplicación si no existe OA asociada. ✅ El costo se imputa al cuartel y al lote de producción a través de la OA.
Validación técnica ⚠️ El operador puede aplicar sin que el agrónomo haya validado el producto. ✅ Sin OA activa y firmada digitalmente, el CSP no acepta el registro.

2.2 Cómo el ERP OA cierra el ciclo

👨‍🌾
Agrónomo
Crea OA en el ERP. Define producto, cuartel, dosis objetivo.
📋
ERP genera n° OA
Número único correlativo. Se imprime o envía al operador.
🚜
Operador ejecuta
Ingresa el n° OA en el CSP. Completa condiciones reales de aplicación.
✅
Ciclo cerrado
ERP consolida OA + CSP. CPA se genera automáticamente.
⚠️

OA retroactivas para registros históricos

Para los registros CSP existentes (sin n° OA), el ERP debe permitir crear OA retroactivas. El flujo inverso: CSP → OA (en lugar de OA → CSP). El sistema importa los campos del CSP, crea la OA con estado "Cerrada/Retroactiva" y puebla el campo n° OA en el Excel histórico. Este proceso de backfill puede automatizarse con un script Python de migración (ver Fase 1 del Plan de Acción).

3
Recomendación — Arquitectura Óptima
CSP como núcleo, OA como motor de planificación, CPA como subproducto automático

La arquitectura recomendada no reemplaza el CSP ni el CPA. Los integra en un flujo único donde cada sistema hace lo que mejor sabe hacer, eliminando doble digitación y maximizando la calidad del dato.

3.1 Principios de diseño

💡

Un solo punto de entrada, múltiples salidas

  • El operador solo llena el CSP (o la interfaz web equivalente). No llena el CPA por separado.
  • El agrónomo solo usa el ERP para planificar y emitir OA.
  • El CPA se genera automáticamente como reporte PDF desde el CSP al final de cada mes.
  • El ERP actúa como hub de integración: recibe datos del CSP y expone reportes al SAG/ASOEX.

3.2 Flujo de datos recomendado

Paso Actor Instrumento Acción Resultado
1. Planificación Agrónomo ERP OA Crea OA: especie, cuartel, producto, dosis objetivo, fecha planificada. Se genera n° OA. Se valida carencia y restricción de uso automáticamente.
2. Exportación CSV Sistema (automático) ERP → CSV ERP exporta la OA en formato CSV con los campos del CSP precargados. Operador recibe CSV o ficha impresa con n° OA y datos de la orden.
3. Ejecución Operador CSP (Excel/Web) Importa CSV de OA. Completa campos de ejecución real: clima, mojamiento real, dosis real, hora, maquinaria. Fila CSP completa. n° OA poblado. Cálculos automáticos de desvío y carencia.
4. Cierre OA Sistema (automático) CSP → ERP CSP exporta fila completada al ERP. ERP cierra la OA y registra desvíos. OA cerrada. Inventario descontado. Alerta si desvío supera umbral.
5. Generación CPA Sistema (automático) ERP → PDF/Excel Al cierre de mes el ERP filtra los 13 campos CPA y genera el reporte oficial. CPA listo para firma del responsable técnico y archivado SAG.

3.3 Reglas de negocio críticas a implementar en el ERP

  • ⛔ Validación de carencia: si fecha_cosecha < fecha_aplicación + carencia_días, bloquear la OA y notificar al agrónomo.
  • ⛔ Validación de reingreso: si fecha_reingreso > hoy, emitir alerta de acceso restringido al cuartel.
  • ⚠️ Alerta de desvío: si abs(% desvío) > 10%, notificar al agrónomo con detalle de producto, cuartel y aplicador.
  • ✅ Validación SAG: verificar que el Reg SAG del producto esté vigente en la base de datos del SAG antes de emitir la OA.
  • 📊 Límite de uso: alertar cuando el uso acumulado de un IA supere el límite anual permitido por el SAG para ese cultivo.

Contingencia en Excel / Google Sheets
Cómo mantener la operación si el ERP cae o no está disponible
⚠️

El CSP Excel ES el sistema de contingencia

Si el ERP OA no está disponible (corte de internet, mantenimiento, fallo del servidor), el operador continúa llenando el CSP normalmente. El campo n° OA queda vacío temporalmente y se backfilla cuando el sistema vuelva. Lo crítico es no perder ninguna fila de aplicación y garantizar los cálculos de carencia y reingreso.

📁 Hojas que deben existir en el Excel
  • Aplicaciones — hoja principal, 55 columnas, una fila por producto × cuartel.
  • Productos — catálogo: nombre comercial, IA, Reg SAG, carencia etiqueta, carencia ASOEX, reingreso días.
  • Cuarteles — código, nombre, superficie ha, especie, variedad.
  • Aplicadores — RUT, nombre, certificación vigente hasta.
  • Maquinaria — código, tipo, capacidad (L), calibración vigente.
  • CPA_mensual — hoja de solo lectura generada por macro con los 13 campos del CPA.
  • Resumen_temporada — tabla dinámica: litros/kg usados por producto y cuartel.
📤 Qué exportar diariamente al final de la jornada
  • Guardar copia del Excel en: CSP_YYYYMMDD.xlsx en Google Drive (carpeta compartida con el agrónomo).
  • Exportar hoja "Aplicaciones" como CSV: aplicaciones_YYYYMMDD.csv — insumo para el ERP cuando vuelva.
  • Exportar hoja "CPA_mensual" como PDF al cierre de cada mes.
  • Verificar que las columnas ¿Puedo ingresar? y ¿Puedo cosechar? no tengan ❌ para cuarteles activos.
  • Nunca borrar filas — marcar con estado "Anulada" si corresponde.

5.1 Fórmulas críticas en Excel

Estas fórmulas deben estar presentes en las columnas correspondientes de la hoja "Aplicaciones". Se asume que la fila de datos comienza en la fila 2 y que la hoja de productos se llama "Productos".

Carencia etiqueta (traída desde tabla Productos):

=BUSCARV(T2, Productos!$A:$H, 5, 0) -- T2 = Nombre comercial del producto -- Columna 5 en Productos = Carencia etiqueta (días)

Fecha fin carencia:

=A2 + X2 -- A2 = Fecha aplicación -- X2 = Carencia etiqueta (días) -- Formato celda: DD/MM/YYYY

¿Puedo cosechar? (valida contra fecha cosecha programada):

=SI(Y2="", "Sin fecha cosecha", SI(AX2 <= Y2, "✅ SÍ", "❌ NO — faltan " & TEXT(Y2 - AX2, "0") & " días")) -- Y2 = Fecha cosecha programada -- AX2 = Fecha fin carencia

Fecha reingreso:

=A2 + BUSCARV(T2, Productos!$A:$I, 6, 0) -- Columna 6 en Productos = Reingreso días

¿Puedo ingresar? (valida contra hoy):

=SI(AZ2 <= HOY(), "✅ SÍ — Reingreso habilitado", "❌ NO — Hasta " & TEXTO(AZ2, "DD/MM/YYYY")) -- AZ2 = Fecha reingreso calculada

% Desvío dosis:

=SI(AH2=0, "Sin dato", TEXTO((AG2 - AH2) / AH2, "0.0%")) -- AG2 = Dosis real L/ha -- AH2 = Dosis objetivo L/ha

Diferencia de volumen:

=AI2 - AJ2 -- AI2 = Volumen real aplicado (L) -- AJ2 = Volumen teórico calculado (L)

Superficie cubierta %:

=SI(P2=0, 0, AB2 / P2) -- AB2 = Superficie tratada (ha) -- P2 = Superficie cuartel (ha) -- Formato celda: 0.0%

Criterio de priorización

Los temas están ordenados por su impacto directo en las fases del plan de acción. No es necesario dominarlos todos antes de empezar — se pueden aprender en paralelo a medida que avanza el proyecto. El tiempo indicado es el mínimo para ser operativamente funcional, no para llegar a nivel experto.

Por qué: Es el lenguaje del ERP (Flask), de los scripts de migración (openpyxl), de los reportes (Pandas) y de la automatización de exportación CSV. Todo el proyecto depende de Python. Sin él no se puede escribir ni entender ninguna parte del código del ERP.

📚 Recurso gratuito: Tutorial oficial Python en español (docs.python.org) + Automate the Boring Stuff with Python (automatetheboringstuff.com — gratuito online). Enfocarse en: variables, listas, diccionarios, bucles, funciones, archivos CSV y JSON.

Por qué: El ERP usa SQLAlchemy sobre SQLite/PostgreSQL. 🐼

Pandas (Python)

Por qué: El script de migración CSP → OA lee el Excel con pandas.read_excel(). El módulo de exportación al CPA filtra columnas con df[columnas_cpa]. El análisis de desvíos y el resumen de temporada son operaciones nativas de Pandas (groupby, merge, pivot_table). Sin Pandas, cada operación requiere escribir el doble de código Python puro.

📚 Recurso gratuito: Tutoriales oficiales Pandas + Kaggle Learn — Pandas (gratuito). Priorizar: read_excel, read_csv, filtrado, merge y to_csv.

20h ~2.5 semanas

📚 Recurso gratuito: Tutorial oficial Flask (Flaskr) + The Flask Mega-Tutorial de Miguel Grinberg (miguelgrinberg.com — parte 1 a 8 gratuitas).

Con Git se puede trabajar en la Fase 2 sin romper la Fase 1, hacer rollback si algo falla en producción, colaborar con otros desarrolladores y mantener un historial de cambios legible (quién cambió qué y por qué). Es el seguro de vida del desarrollo de software.

📚 Recurso gratuito: Learn Git Branching (interactivo, en español) + Pro Git Book en español (git-scm.com). Dominar: init, add, commit, push, pull, branch, merge y rebase básico.
